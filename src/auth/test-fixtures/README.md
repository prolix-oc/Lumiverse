# Auth upgrade fixture

`better-auth-1.7.2.json` contains synthetic credentials and a signed session
cookie generated by the actual `better-auth@1.7.2` package. It contains no
installation data or real credentials. Its secret and plaintext password are
deliberately public test values.

It was generated in a separate temporary Bun project with that exact version,
using an in-memory `bun:sqlite` database, `getMigrations(options).runMigrations()`,
the username and admin plugins, and `POST /api/auth/sign-up/email` at
`http://localhost:7860`. The options used the fixture's secret and enabled
email/password authentication. The resulting `user`, `account`, and `session`
rows and the `better-auth.session_token` cookie were exported. Only the stored
session expiration was extended to `2100-01-01T00:00:00.000Z` so the regression
test does not expire after seven days.

The upgrade integration test imports the stored rows without changing their
date serialization, applies Lumiverse's migrations, then validates the old
cookie and password through the upgraded application. It requires no legacy
package installation at test time.
